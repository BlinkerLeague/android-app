# 점수 항목 확장안 (제안)

> 상태: **7개 항목 앱 판정 반영(2026-11-15)**. 서버 8개 점수 항목 중 회전 깜빡이 외 `SIGNAL_CANCEL` · `TURN_SPEED` · `SMOOTH_DRIVING` · `NIGHT_HEADLIGHT` · `SEAT_BELT` · `SAFETY_WARNING` · `RAIN_DRIVING`을 앱이 판정해 보냅니다(결정은 `plan.md` 결정 기록 2026-11-15). 나머지 항목(과속 등)은 아직 제안입니다.
> 근거 데이터: [`sdk-test-log.md`](sdk-test-log.md)(이 문서에서 "로그"), 팀원 조사 `feature/vehicle-background-speed`의 `docs/spikes/`.
> 점수 계산은 서버가 합니다(서버 `plan.md` 3.3·4.1). 앱은 판정한 이벤트만 보냅니다. 팀에서 확정하면 [`server-requests.md`](server-requests.md)로 서버 팀에 전달합니다.
> 작성: 2026-11-04

## 1. 왜 늘리나

지금 계획(서버 `plan.md` 3.3, 4.1)의 항목은 4개이고, MVP에서 실제로 계산하는 것은 **회전 깜빡이 하나**입니다.

- 회전이 적은 운행은 점수가 회전 2~3번으로 결정됩니다. 운이 크게 작용합니다.
- 성공·실패 2단계라 만점이 쉽습니다. 실력 차이가 점수에 드러나지 않습니다.
- 속도처럼 안전과 직결되는 행동이 점수에 전혀 반영되지 않습니다.

## 2. 객관성을 위한 원칙

1. **기준을 법규에서 가져옵니다.** 임의로 정한 숫자보다 법정 기준이 설득력이 있습니다(아래 표의 "근거"). 법 조항 번호는 제출 전에 원문으로 다시 확인합니다.
2. **판정을 내비가 이미 했으면 그 값을 씁니다.** 예: 단속 카메라 과속 여부는 `CameraAlert.isOverSpeed`를 그대로 씁니다.
3. **횟수는 거리로 나눕니다.** 10km당·100km당으로 바꿔 긴 운행과 짧은 운행을 같은 잣대로 봅니다.
4. **표본이 적으면 계산하지 않습니다.** 항목마다 최소 표본(예: 회전 3번, 제한속도를 아는 구간 5분)을 두고, 모자라면 `NOT_APPLICABLE`로 둡니다. 1~2번의 우연으로 점수가 크게 흔들리지 않게 합니다.
5. **차량이 지원하지 않는 항목은 빼고 가중치를 다시 나눕니다.** 기존 규칙(서버 4.1)과 같습니다. 그 항목 때문에 0점이 되지 않습니다.
6. **기준값은 전부 설정값입니다.** 앱 `domain/config`와 서버 `GET /api/config/thresholds`에 두고, 코드에 적지 않습니다.
7. **위치 좌표는 보내지 않습니다.** 새 이벤트에도 좌표를 넣지 않습니다. 카메라·주의 구간은 종류와 속도만 보냅니다.

## 3. 항목 목록

데이터 상태는 다음 세 단계로 표시합니다.

- 🟢 에뮬레이터에서 값과 변경 콜백을 확인했습니다. 앱 판정 로직만 만들면 됩니다.
- 🟡 읽기는 확인했습니다. 변경 콜백이나 실차 동작은 미확인입니다.
- 🔴 에뮬레이터에서 값이 오지 않았습니다. 실차 확인이 필요합니다.

## 4. 가중치 (초안)

카테고리로 묶고, 측정한 항목끼리 가중치를 다시 나눕니다(합 1.0).

| 카테고리 | 항목 (가중치) | 소계 |
|---|---|---|
| 신호 | `TURN_SIGNAL` 0.25, `SIGNAL_CANCEL` 0.05, `NAVI_TURN_SIGNAL` 0.05 | 0.35 |
| 속도 | `SPEED_LIMIT` 0.10, `ENFORCEMENT` 0.05, `CAUTION_ZONE` 0.10, `TURN_SPEED` 0.05 | 0.30 |
| 부드러운 운전 | `SMOOTH_DRIVING` 0.15 | 0.15 |
| 출발 준비·차량 | `SEAT_BELT` 0.05, `SAFETY_WARNING` 0.05 | 0.10 |
| 시야 | `NIGHT_HEADLIGHT` 0.05, `RAIN_DRIVING` 0.05 | 0.10 |

- 게임 이름(깜빡이리그)에 맞게 신호 비중을 가장 크게 둡니다.
- 2차 시점에 🔴 항목이 실차에서 확인되지 않으면, 그 항목은 `supported`에 들어가지 않아 자동으로 빠집니다.
- 그러면 🟢 항목만으로 계산합니다: 회전 깜빡이 4단계, 깜빡이 끄기, 회전 속도, 급가속·급감속, 야간 전조등, 경고등. **이것만으로도 지금(1개)보다 6배 많은 항목**입니다.

## 5. 게임 요소·난이도

- **만점이 어려워집니다.** 회전 깜빡이를 "30m 전 제때"로 바꾸고 항목이 늘어 S등급(95점)이 쉽게 나오지 않습니다.
- **항목별 상세 화면(SCR-02b)**: "30m 전에 켠 회전 4/5", "깜빡이 끄기 잊음 1회"처럼 무엇을 고치면 되는지 바로 보입니다.
- **미션 소재가 늘어납니다.** 모두 안전 행동을 보상합니다.
  - "오늘 회전 5번 모두 30m 전에 깜빡이" (기존 "회전 깜빡이 완벽"의 상위 난이도)
  - "벨트 매고 출발 7일 연속"
  - "어린이보호구역 모두 시속 30km 이하"
  - "깜빡이 끄기 잊지 않기"
  - "비 오는 날 전조등 켜고 운전"
- **배지 소재**: 항목별 누적 기록(예: 제때 깜빡이 100회, 단속 구간 50곳 무위반).
- **리그 공정성**: 차량마다 지원 항목이 달라, 지원 항목이 적은 차가 유리할 수 있습니다.
  - 리그 순위에는 **모든 차가 측정할 수 있는 공통 항목 점수**만 쓰는 방안을 제안합니다. 예: 신호·급가감속·회전 속도.
  - 서버 `plan.md` 4.4의 "같은 측정 항목 집단끼리 비교" 결정 사항과 연결됩니다.

## 6. 앱이 새로 보낼 이벤트 (서버 형식 제안)

`supported`는 서버 `ScoreItem` 이름(위 항목 이름)으로 보냅니다. 앱은 항목에 필요한 신호가 모두 있을 때만 그 항목을 넣습니다(예: `TURN_SPEED` = 조향각 + 속도, `RAIN_DRIVING` = 와이퍼 + 하향등).

> 서버는 모르는 이벤트 종류·항목 이름을 400으로 거부하고, 앱은 4xx를 재전송하지 않아 운행 전체가 버려집니다. **서버 P1 반영이 배포된 뒤에만 새 값을 보냅니다**(서버 plan.md D21). 서버 반영 계획은 서버 plan.md D18~D21, 4.1, 4.6.

| 이벤트 `type` | payload | 비고 |
|---|---|---|
| `TURN` (확장) | `{ direction, signalOn, signalTiming: ON_TIME/LATE/WRONG_DIRECTION/NONE, leadDistanceM, maxSpeedKmh }` | `signalOn`은 호환을 위해 유지 |
| `SIGNAL_LEFT_ON` | `{ durationSec }` | |
| `NAVI_TURN` | `{ turnType, signalOnTime }` | |
| `SPEEDING_SUMMARY` | `{ knownLimitSec, overLimitSec }` | 운행당 1건 |
| `CAMERA_PASS` | `{ cameraType, overSpeed, overSectionAvrSpeed }` | 좌표 없음 |
| `CAUTION_ZONE` | `{ zoneType, maxSpeedKmh, limitKmh }` | 좌표 없음 |
| `SEAT_BELT` | `{ buckledAtDeparture, unbuckledMovingSec }` | 운행당 1건 |
| `NIGHT_SEGMENT` (수정) | `{ durationSec, headlightOffSec }` | `autoLight` 제거 |
| `RAIN_SEGMENT` | `{ durationSec, headlightOffSec, knownLimitSec, overRainLimitSec }` | |
| `HARSH_ACCEL` / `HARSH_BRAKE` / `SAFETY_WARNING` | 기존 계획대로 | |
