## 2. 화면이 쓰는 SDK 데이터

화면은 SDK를 직접 쓰지 않습니다. `data/vehicle`이 Flow로 바꿔 주는 값만 씁니다.

| 화면에서 필요한 것 | 출처 (조사 결과) | 권한 | 비고 |
| --- | --- | --- | --- |
| 정차 여부: 기어 | Vehicle `Gear`: `getCurrentGearSelectionState`, `registerGearSelection` → `onSelected(VehicleGear?)` | `CAR_DRIVE` | 에뮬레이터 확인 완료 |
| 정차 여부: 속도 | CarProperty `PERF_VEHICLE_SPEED` (m/s, 약 10Hz) | `CAR_SPEED` (런타임) | Vehicle SDK에는 속도가 없음. 10Hz 구독은 포그라운드 서비스(A9) 안에서만 함 |
| 시동 | **없음** | — | `IgnitionState` enum만 있고 값을 돌려주는 API는 없음. 화면 판단에 쓰지 않음 |
| 측정 가능 항목 (SCR-00, SCR-02) | `checkXXXCapability` 결과 → `CapabilityReport` (A1) | — | 미지원 항목은 "이 차량 미지원"으로 표시 |
| 기록 상태 (SCR-01, DRV) | A9 서비스 실행 여부 | — | 서비스가 꺼져 있으면 "기록이 꺼져 있어요" |

코드와 맞지 않는 부분이 있습니다. `domain/model/VehicleState.kt`의 `VehicleStateSample.ignitionOn`은 SDK로 받을 수 없는 값입니다. A3(운행 구분) 작업 때 기어·속도 기준으로 바꿔야 하고, 화면 쪽은 이 값을 쓰지 않습니다.

## 3. 주행 안전 가드 (A11): 가장 먼저 만듦

### 판정 (순수 함수, `domain/detection/DrivingGuard`)

입력은 최신 기어, 속도, 속도 지원 여부입니다. 출력은 `Parked` 또는 `Driving`입니다.

| 기어 | 속도 | 결과 |
| --- | --- | --- |
| P | 0 또는 측정 안 됨 | Parked |
| P | > 0 | Driving (안전 쪽으로 판단) |
| D·R·N | 아무 값 | Driving |
| UNKNOWN (값 없음·capability 실패) | — | Driving |

- 기어 값을 못 받으면 화면을 열지 않습니다. 대신 "차량 상태를 확인할 수 없어요"를 보여줍니다. 기준이 너무 엄격하면 시연이 막히므로 디버그 빌드에서만 우회 옵션을 둡니다.
- 정차 판정은 "기어 P"로만 합니다. 기획서의 "정차 또는 P단"에서 "정차"(D단 속도 0)는 신호 대기와 구분할 수 없어 P0에서 빼고, 결정 기록에 남깁니다.
- 기준값(속도 임계값 등)은 `domain/config`에서 읽습니다.

### 화면 연결

- `MainActivity`의 최상위에서 `DrivingGuardViewModel.state`를 구독합니다.
  - `Driving`이면 NavHost 대신 DRV 화면만 그립니다. 백스택은 유지하므로 P로 돌아왔을 때 보던 화면이 그대로 남습니다.
  - `Parked`이면 NavHost를 그립니다.
- P로 돌아와도 화면을 **자동으로 띄우지 않습니다.** 앱이 이미 앞에 있을 때만 정차 화면으로 바뀝니다.
- 다이얼로그, 토스트, 알림으로 점수를 보여주는 경로는 만들지 않습니다. 서비스 알림은 "깜빡이리그 · 기록 중" 한 줄입니다.

### DRV 기록 중 화면

- 아이콘 + "기록 중" + "정차하면 결과를 볼 수 있어요" 정도만 둡니다.
- 숫자, 점수, 버튼을 두지 않습니다.
- 서비스가 꺼져 있으면 "기록이 꺼져 있어요"를 표시합니다.

### 완료 기준 (단위 테스트 + 에뮬레이터)

- 위 표의 모든 행
- SCR-02를 보는 중 Virtual Console에서 기어 D로 바꾸면 1초 안에 DRV로 전환
- 주행 중 앱 아이콘을 눌러도 DRV만 보임
- P로 돌아오면 보던 화면으로 복귀

## 4. 화면별 계획

화면 규칙은 다음과 같습니다.
- 파일은 `ui/<feature>/XxxScreen.kt`, `XxxViewModel.kt`, `XxxUiState.kt`로 나눕니다.
- Screen(상태 연결)과 Content(stateless)를 분리합니다.
- ViewModel은 `StateFlow<XxxUiState>` 하나만 노출합니다.

### 4.1 내비게이션 (`ui/navigation/BlinkerNavHost.kt` 재구성)

| 경로 | 화면 | 지금 |
| --- | --- | --- |
| `onboarding` | SCR-00 | 없음 |
| `home` | SCR-01 | 없음 (지금 시작 화면은 `demo`) |
| `result/{tripId}` | SCR-02 | `summary/{tripId}`를 확장 |
| `result/{tripId}/plays` | SCR-02a | 없음 (지금은 SCR-02 안의 회전 목록) |
| `quest` | SCR-03 | `missions`를 확장 |
| `demo` | 시나리오 재생 | 디버그 빌드에서만 홈에 진입 버튼 |

- 시작 화면은 저장된 토큰이 없으면 `onboarding`, 있으면 `home`입니다.
- 운행이 끝나 결과가 생겨도 자동으로 이동하지 않습니다. 홈의 "최근 경기"에서 들어갑니다.
  - 예외: 데모 재생이 끝나면 지금처럼 결과로 이동합니다.

### 4.2 SCR-00 온보딩 (`ui/onboarding`)

- **단계:**
  1. 닉네임(2~12자)
  2. 시·도 → 시군구 선택
  3. 내 차량 측정 가능 항목 (`CapabilityReport`)
  4. 속도 권한 요청
  5. "리그 입장"
- **UiState:** `step`, 입력값, `nicknameError`(중복·길이), `capabilities`, `speedPermission`(허용/거부/미요청), `submitting`
- **의존:** A8 등록 API·토큰 저장. HTTP 클라이언트 결정 전까지는 Fake API로 만듭니다.
- **주의:**
  - 키보드 입력은 정차 중에만 합니다(가드가 보장).
  - 시군구 목록은 앱에 넣습니다(서버에 좌표를 보내지 않음).
- **결정 필요:** `CAR_SPEED` 거부 시 처리. 제안은 기어 D일 때만 회전으로 보고 "판정 정확도 제한"을 표시하는 것입니다.

### 4.3 SCR-01 홈 (`ui/home`)

- **구성:**
  - 오늘의 퀘스트 카드 (S5)
  - 연승 (D6 결정 전에는 숨김)
  - 최근 경기 2건 (S4)
  - 기록 상태 줄 (A9)
- **UiState:** `quest: QuestCardState?`, `recentTrips: List<RecentTripRow>`, `recordingStatus`, `notices: List<Notice>`(속도 권한 없음, 기록 꺼짐)
- **최근 경기 행:**
  - 점수·등급
  - 서버 상태에 따라 "짧은 이동은 경기에서 제외돼요", "측정할 회전이 없었어요"
  - 로컬 업로드 대기열에 있으면 "결과 집계 중"
- **데이터:**
  - Room의 최근 운행 2건을 먼저 보여주고, S4 응답이 오면 덮어씁니다.
  - 지금 `TripApi`에는 업로드만 있으므로 `getRecentTrips`, `getScore`를 추가하고 Fake 구현도 함께 둡니다.
- **하단 탭:** 홈만 활성. 리그·지갑 등은 P1이라 P0에서는 탭을 그리지 않습니다(비활성 탭은 터치 혼란을 만듦).

### 4.4 SCR-02 경기 결과 (`ui/summary` → `ui/result`로 이름 변경)

- **지금:** 점수·상태 안내, 깜빡이 횟수, 회전 목록, 오늘 미션 카드가 있습니다.
- **바꿀 것:**
  - 평점 + 등급(S95·A85·B70·C50). 50 미만 표기는 결정 전까지 등급 칸을 비웁니다.
  - 항목별 점수 행:
    - P0은 깜빡이만 값이 있고, 나머지(부드러운 가감속·안전 경고·야간 전조등)는 회색 "준비 중"으로 둡니다.
    - 미지원 항목은 "이 차량 미지원"으로 둡니다.
  - 회전 목록은 SCR-02a로 옮기고, SCR-02에는 "득점 1 · 실점 1"과 "플레이 보기" 버튼만 남깁니다.
  - 퀘스트 판정 카드 → SCR-03
- **상태 (sealed):**
  - `Loading`
  - `Pending` (로컬 요약 + "결과 집계 중")
  - `Scored`
  - `NoTurn`
  - `ExcludedShort`
  - `NotFound`
- **데이터 흐름:**
  1. Room의 로컬 판정 결과(거리, 득점·실점)를 즉시 표시합니다.
  2. 업로드 응답이나 S3 `GET /api/trips/{id}/score`가 오면 갱신합니다.
  - 오프라인이어도 화면은 열립니다.
- **문구:** 최소 거리는 숫자로 쓰지 않고 "짧은 이동"으로 씁니다(기준값이 서버에서 바뀜).

### 4.5 SCR-02a 플레이 타임라인 (`ui/result/plays`)

- 시각순 플레이 카드입니다. 시각, 좌·우 아이콘, 득점(파랑)·실점(주황), 깜빡이를 켠 시점("3초 전")을 보여줍니다.
- 가로 스크롤 `LazyRow`. 카드 최소 높이 120dp, 터치 영역 64dp 이상
- 카드 탭으로 들어가는 SCR-02b 항목 상세는 P1이므로 P0에서는 탭 동작이 없습니다.
- 데이터: S3 `plays`가 있으면 그것을 쓰고, 없으면 로컬 `TurnRecord`를 씁니다.

### 4.6 SCR-03 퀘스트 상세 (`ui/missions` → `ui/quest`)

- **구성:**
  - 퀘스트 제목
  - 조건별 진행도: 회전 2/3, 깜빡이 100%
  - 상태: 진행 중·달성·실패
  - 보상 "20P" (P1 표시)
  - "다음 경기에서 재도전"
- `TodayMission` 모델을 S5 응답의 `conditions[]` 구조에 맞게 넓힙니다. 지금은 회전 수만 있습니다.
- "빨리 도착"처럼 위험을 유도하는 문구는 쓰지 않습니다.

## 5. 예외 상태 (A12) 매핑

| 상태 | 판단 | 문구 | 화면 |

| 회전 0회 | 서버 `NO_TURN` | 측정할 회전이 없었어요 · 이번 경기는 평점 없이 기록돼요 | SCR-02, 홈 최근 경기 |

## 6. 레이아웃·디자인 규칙

- 테마는 `ui/theme`의 팔레트를 그대로 씁니다(배경 #101317, 카드 #1B2027, 강조 #5AA2FF, 득점 파랑·실점 주황).
- Pleos에서 앱은 오른쪽 영역에만 그려지므로 고정 크기 대신 `fillMaxSize`와 `weight`를 씁니다.
  - Preview는 1280×720과 좁은 폭 두 가지로 확인합니다.
  - 실제 폭은 에뮬레이터에서 재서 이 문서에 적습니다.
  - **측정값 (2026-11-08, Pleos Connect 에뮬레이터 2560×1440, 160dpi)**: 앱 영역 **1682×1210dp** (화면 x 853~2535, y 90~1300). 왼쪽 차량 상태 패널과 위 상태 바·아래 공조 바를 뺀 영역
- 한 화면의 핵심 숫자는 1개(평점)로 하고, 나머지는 보조 텍스트로 둡니다.
- 모든 버튼과 카드의 터치 영역은 64dp 이상입니다.
