## 2. 화면이 쓰는 SDK 데이터

화면은 SDK를 직접 쓰지 않습니다. `data/vehicle`이 Flow로 바꿔 주는 값만 씁니다.

| 화면에서 필요한 것 | 출처 (조사 결과) | 권한 | 비고 |
| --- | --- | --- | --- |
| 정차 여부: 기어 | Vehicle `Gear`: `getCurrentGearSelectionState`, `registerGearSelection` → `onSelected(VehicleGear?)` | `CAR_DRIVE` | 에뮬레이터 확인 완료 |
| 정차 여부: 속도 | CarProperty `PERF_VEHICLE_SPEED` (m/s, 약 10Hz) | `CAR_SPEED` (런타임) | Vehicle SDK에는 속도가 없음. 10Hz 구독은 포그라운드 서비스(A9) 안에서만 함 |
| 시동 | **없음** | — | `IgnitionState` enum만 있고 값을 돌려주는 API는 없음. 화면 판단에 쓰지 않음 |
| 측정 가능 항목 (SCR-00, SCR-02) | `checkXXXCapability` 결과 → `CapabilityReport` (A1) | — | 미지원 항목은 "이 차량 미지원"으로 표시 |
| 기록 상태 (SCR-01, DRV) | A9 서비스 실행 여부 | — | 서비스가 꺼져 있으면 "기록이 꺼져 있어요" |

`VehicleStateSample.ignitionOn`은 SDK로 받을 수 없어 알 수 없으면 null이고, 운행 구분은 기어 · 속도 기준입니다(11.08, #22). 화면은 이 값을 쓰지 않습니다.

## 3. 주행 안전 가드 (A11): 가장 먼저 만듦

### 판정 (순수 함수, `domain/detection/DrivingGuard`)

입력은 최신 기어, 속도, 속도 지원 여부입니다. 출력은 `Parked` 또는 `Driving`입니다.

| 기어 | 속도 | 결과 |
| --- | --- | --- |
| P | 0 또는 측정 안 됨 | Parked |
| P | > 0 | Driving (안전 쪽으로 판단) |
| D·R·N | 아무 값 | Driving |
| UNKNOWN (값 없음·capability 실패) | — | Driving |

- 기어 값을 못 받으면 화면을 열지 않습니다. 대신 "차량 상태를 확인할 수 없어요"를 보여줍니다. 기준이 너무 엄격하면 시연이 막히므로 디버그 빌드에서만 우회 옵션을 둡니다.
- 정차 판정은 "기어 P"로만 합니다. 기획서의 "정차 또는 P단"에서 "정차"(D단 속도 0)는 신호 대기와 구분할 수 없어 P0에서 뺍니다(결정 기록에는 아직 없음, 9장 "적용 중").
- 기준값(속도 임계값 등)은 `domain/config`에서 읽습니다.

### 화면 연결

- `MainActivity`의 최상위에서 `DrivingGuardViewModel.state`를 구독합니다.
  - `Driving`이면 NavHost 대신 DRV 화면만 그립니다. 백스택은 유지하므로 P로 돌아왔을 때 보던 화면이 그대로 남습니다.
  - `Parked`이면 NavHost를 그립니다.
- P로 돌아와도 화면을 **자동으로 띄우지 않습니다.** 앱이 이미 앞에 있을 때만 정차 화면으로 바뀝니다.
- 다이얼로그, 토스트, 알림으로 점수를 보여주는 경로는 만들지 않습니다. 서비스 알림은 "깜빡이리그 · 기록 중" 한 줄입니다.

### DRV 기록 중 화면

- 아이콘 + "기록 중" + "정차하면 결과를 볼 수 있어요" 정도만 둡니다.
- 숫자, 점수, 버튼을 두지 않습니다.
- 서비스가 꺼져 있으면 "기록이 꺼져 있어요"를 표시합니다.

### 완료 기준 (단위 테스트 + 에뮬레이터)

- 위 표의 모든 행
- SCR-02를 보는 중 Virtual Console에서 기어 D로 바꾸면 1초 안에 DRV로 전환
- 주행 중 앱 아이콘을 눌러도 DRV만 보임
- P로 돌아오면 보던 화면으로 복귀

## 4. 화면별 계획

화면 규칙은 다음과 같습니다.
- 파일은 `ui/<feature>/XxxScreen.kt`, `XxxViewModel.kt`, `XxxUiState.kt`로 나눕니다.
- Screen(상태 연결)과 Content(stateless)를 분리합니다.
- ViewModel은 `StateFlow<XxxUiState>` 하나만 노출합니다.
